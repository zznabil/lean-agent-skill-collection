# V9.0.1 - standards at the point of use

## Scope and decisions

The authorised V9.0.1 change ships the V9.0.0 local candidate after restoring concrete standards activation. The pinned public baseline is V8.7.0 commit 71e5c44e97be8fd2808288de57ea574cc3c252e2. All 97 historical register rows were inspected, including globally rejected, watched and deferred entries.

Keep one actual owner per rule and group sources only when they inform the same behaviour. Keep trigger, action and source together in the owning root or local reference. Root descriptions stay short. References have explicit local load conditions; no skill needs an absent sibling profile. Each skill carries a minimal communication fallback because skill discovery does not guarantee global-policy injection. Do not repeat full standards explanations or introduce a standards controller.

The register retains edition/status, decision, reviewed date, next review and original source. Its owner column now resolves to real files. STANDARDS-COVERAGE.json binds every row to an explicit trigger, behaviour and reference and declares its limited structural scope. Source-review dates are not refreshed by an ownership repair.

## Source-derived design

Reviewed public guidance on 7 September 2026: [GPT-5.6](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6), [GPT-6 Astra](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra), [skill authoring](https://developers.openai.com/codex/build-skills) and [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use). The model guidance and skill documentation inform concise intent, clear boundaries and progressive disclosure. GitHub guidance supports pinned actions and least privilege. These sources do not validate this collection's model outcomes.

Detailed behaviours are independently distilled from the project's preserved V8.7/V9 source and recorded adoption decisions, not copied proprietary clauses. No new claim about the latest edition of all 97 sources is made.

## Acceptance boundaries

Recalculate instruction size from bytes and whitespace words; neither is a token measurement. Preserve the V9 ceilings. Test exact inventories, checksum coverage, archive/source identity, links and standalone packaging. Add positive and isolated negative controls for source ownership, missing rule components, inactive-source promotion and missing per-skill communication. Changing the oracle must not manufacture a pass.

Run both supported PowerShell environments before and after protected merge. Build from exact main, use an unused annotated tag and verify every draft/public asset. Do not weaken checks, rewrite published releases or silently update installations. Record real failures and corrected causes in delivery evidence.

Live-model activation, instruction adherence, cross-host equivalence, task outcomes and formal conformance remain unmeasured. Authored scenarios are not executed-model pass rates.
