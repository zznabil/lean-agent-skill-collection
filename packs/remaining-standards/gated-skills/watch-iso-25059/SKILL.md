# ISO/IEC 25059 AI quality model

## Task and boundary
- Revisit the recorded watch entry for ISO/IEC 25059 or its proposed replacement.
- Do not turn a watched source, draft or newly found document into a mandatory quality gate automatically.
- Work only on the selected artifact or assessment. This routine does not grant permission to run attacks, deploy, publish or change
  policy.
- OFF-DEFAULT GUARD: use only for the stated selection or review request; do not install as an always-on workflow.

## Source and limits
- Read [SOURCES.md](SOURCES.md) for the selected edition, official files, source boundaries and copying terms.
- Read the relevant source sections before making a source-specific decision. A compact routine is not the complete specification.
- Historical adoption decision: Watch. Keep this boundary unless an authorised decision explicitly changes it.
- Full licensed text was not obtained. This is a Lean application routine grounded in public scope and existing Lean guidance, not a
  clause transcript.
- Obtain the authorised full text before a clause-level assessment. Do not invent definitions, thresholds or conformity results.

## Procedure
1. Read the recorded decision: ISO/IEC 25059 is a watch entry, not an adopted requirement.
2. Identify the exact published edition or proposed replacement from an authoritative catalogue.
3. Distinguish published, confirmed, draft, withdrawn and superseded states; do not infer one from a search snippet.
4. Record the retrieval date, source identity and what changed relative to the historical register.
5. When a full comparison is required, obtain authorised texts for both the relevant editions.
6. Compare scope, model concepts, compatibility and applicability to the project without inventing missing clauses.
7. Identify what evidence or benefits would justify a separate adoption proposal.
8. Keep current task requirements and existing quality guidance active while the review is unresolved.
9. Do not edit the register, install a skill or alter acceptance rules without an explicit change decision.
10. Return a source-status finding and a bounded recommendation; unknown status is not proof of publication or withdrawal.

## Preserve and verify
- Preserve facts, identifiers, links, required checks, permissions, negation, exceptions and failure/recovery paths.
- Separate planned work, actual evidence and unknown results. Missing or stale evidence is not a pass.
- Do not delete requirements to improve a score or satisfy the line budget; record an unresolved source or task conflict.
- Use the smallest check that can detect the relevant defect. A schema, linter or inventory alone does not prove task success.

## Worked case — authored, not an executed model result
- **Situation:** A search result says a replacement standard is coming, so an agent starts enforcing it.
- **Expected:** Retain watch status and verify publication and explicit adoption before changing any task requirement.
- **Missing-evidence case:** The authoritative catalogue or licensed comparison text is unavailable.

## Finish and stop
- Return the scoped result, evidence, unresolved requirements and next permitted action.
- Make one correction pass and recheck affected evidence. If a required issue remains, report it rather than looping or claiming
  completion.
- Identify the checked scope, source edition, evidence and limits. Do not claim formal conformance or model-behaviour improvement
  from this routine.
