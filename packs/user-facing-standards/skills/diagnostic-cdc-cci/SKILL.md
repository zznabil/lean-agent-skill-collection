# CDC Clear Communication Index: scoped diagnosis

## Use
- Assess defined public information with the CDC Clear Communication Index. Deliver item evidence and a score only after you check the applicable form and material.
- First identify the audience, health-literacy context, objective and main message. Do not use this diagnostic as a universal release gate.

## Source and scope
- Read the official user guide and the appropriate full or modified score sheet linked in SOURCES.md.
- Web review could access the PDFs. The binary downloader received HTTP 403. This folder contains no PDF.
- If you cannot inspect the form or actual material, provide a qualitative review. State why the score is incomplete.

## Procedure
1. Read all material in its delivered form. Include graphics, headings, numbers and visible links.
2. Record the four introductory answers. Select the score sheet for the material’s format.
3. Assess the main message, call to action, their placement and the visual emphasis that supports them.
4. Assess familiar language, active wording for the main message and action, information chunks and meaningful headings.
5. Assess whether the material represents the state of the science. Include remaining uncertainty.
6. Apply the relevant behavioural-recommendation, number and risk items. Use their actual wording and skip logic.
7. Record the observed passage or design evidence for each applicable item. Assign the required zero-or-one rating.
8. Calculate the percentage with the applicable-item denominator. Show ratings and unresolved evidence so others can check the result.
9. Revise defects that evidence supports. Rescore the changed material. Do not remove necessary facts to raise the score.

## Keep the task contract
- The official tool has 20 scored items in seven areas. Use the score sheet to determine applicability, not convenience.
- CDC describes 90 or higher as passing within this tool. Do not treat this as a universal Lean acceptance threshold.
- A score does not replace factual checking, formative research or pretesting with the intended audience.
- Do not infer clinical accuracy, behaviour change or WCAG conformance from a communication score.

## Verify and deliver
- Report the form/version, audience, ratings, calculation, diagnostic issues and actual review limits.
- Distinguish a passing index score from unmet task, safety or evidence requirements.
- Deliver useful findings or revised material first. Include the score only if you calculated it.

## Worked distinction
A clear headline scores well, but the body omits what the reader should do next.
Evaluate the call-to-action items and the real task; the headline alone is not acceptance evidence.

## Communication kernel
If trusted root `AGENTS.md` loads, follow it; otherwise apply this standalone fallback. Do not claim root activation without evidence.
- **Brevity:** Use the fewest words that complete the task. Start with the answer, result or blocker. Remove filler, repeated conclusions, routine narration and decorative headings. Do not add a **Summary** heading or closing **TL;DR**. Use a leading **TL;DR** only when it improves a complex answer.
- **Language:** Use ASD-STE100-inspired short, active sentences and concrete verbs.
- **Terms:** Use ISO 704-inspired consistent terms: one preferred term per distinct concept. Define unfamiliar terms when needed; preserve exact technical and UI strings.
- **Structure:** Use Diátaxis to separate how-to, reference, explanation and tutorial content only when this helps navigation.
- **Integrity:** Preserve facts, actors, conditions, negation, exceptions, permissions, requirements, source rights, uncertainty, evidence, accessibility and the requested voice or format. Do not omit required details just to shorten text.
- **Safety and proof:** Use BCP 14 force only for normative rules. Keep warning-before-hazard, verified safe state, hold points, expected results, failure signs and recovery when relevant. Report actual test outcomes; do not invent a pass.
These are writing guides, not proof of standards conformance or host behaviour. Task-specific source rules still apply.
## Conditional execution rules
- For unchecked results, do not claim compliance or completion.
- In normative text, preserve BCP 14 MUST/SHOULD/MAY force and exceptions. For important requirements, identify one actor, action and observable check.
- Before a hazardous action, state the verified risk and give a warning. For critical steps, use a hold point and check the safe state. When failure is plausible, state the expected result, failure sign and recovery. These controls do not replace task-specific controls.
- Give progress only when requested or useful. Keep progress distinct from the verdict.
- For a difficult mechanism, explain from foundations. For code or configuration, contrast compliant and noncompliant cases only when useful.
