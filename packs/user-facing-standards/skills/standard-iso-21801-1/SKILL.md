# ISO 21801-1: cognitive-accessibility needs

## Use
- Use this skill for barriers to understanding, attention, memory, decisions or recovery in a bounded journey. Provide changes or findings linked to user needs.
- Draft, edit or review as requested. First read the task, users, context and authorised scope.

## Source and scope
- Use ISO 21801-1:2020, confirmed 2025 as the target edition. See SOURCES.md for official access and source status.
- The author did not have the full licensed normative text when preparing this prototype. This skill does not bundle that text.
- This procedure applies Lean guidance to the published scope. It does not reproduce the standard’s clauses.
- For clause-level or conformance work, first obtain an authorised copy. Read the applicable clauses and exceptions. Without that copy, use only supported application guidance. Mark standard-specific requirements as unchecked.

## Procedure
1. Identify the task, users, context and evidence of relevant cognitive-accessibility needs.
2. Map each need to a specific barrier in the current system. Do not treat a diagnosis as a complete profile.
3. Show the task purpose, current state, remaining work and next action where users need them.
4. Keep necessary information available at the decision point. Reduce avoidable memory demands.
5. Use consistent names, clear instructions and coherent chunks. Retain the complete task contract.
6. Reduce unnecessary interruptions. Provide ways to resume after distraction, timeout or navigation away.
7. Make errors recognisable and corrections possible. Provide understandable help and preserve work where supported.
8. Offer an alternative representation or level of support when a demonstrated barrier requires it.
9. Where practical, observe intended users as they find information, understand it, act and recover. Record assistance and untested needs.

## Keep the task contract
- Retain facts, quantities, terms, permissions, prohibitions, conditions, exceptions, warnings and required links.
- Do not invent requirements, numerical thresholds, clause numbers, user needs or evidence to make a checklist appear complete.
- A review or language edit gives no authority for execution, deployment, source acquisition fees or user-data collection.
- These human-oriented principles can inform agent instructions. They do not prove how an agent will interpret those instructions.

## Verify and deliver
- Check the actual task and a relevant failure or recovery path. Use evidence from intended users when available.
- Report source-verified clause findings separately from Lean design suggestions and unchecked items.
- Return the artifact or scoped findings first. State material limits and the evidence needed to resolve them.
- Do not claim formal conformance on the basis of this short routine, a readability score or an unexecuted review plan.

## Worked distinction
A multi-page procedure restarts from the beginning after an interruption.
Expose the last verified state and next permitted action; do not infer that unfinished steps were completed.
