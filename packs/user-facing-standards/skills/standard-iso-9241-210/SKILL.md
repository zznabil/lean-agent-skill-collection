# ISO 9241-210: human-centred design cycle

## Use
- Use only for the named user-information or interface task below; choose draft, edit or review from the request.
- Use when planning or assessing design work that must reflect people, tasks and contexts of use.
- Read the target artifact, intended audience, task and authorised scope before changing it.

## Source and scope
- Target edition: ISO 9241-210:2019. Official access and source status are in SOURCES.md.
- The full licensed normative text was not available when this prototype was authored and is not bundled.
- The steps below are a Lean application routine based on the published scope and existing Lean guidance, not all
  clauses.
- For clause-level or conformance work, obtain an authorised copy and read the applicable clauses and exceptions
  first.
- Without that copy, do only the supported application work and label the unverified standard-specific requirements.

## Procedure
1. Define the interactive system, intended users, affected stakeholders and the real context of use.
2. Inspect existing user research and task evidence before assuming what users need.
3. Turn supported user needs into explicit user requirements and observable evaluation criteria.
4. Generate design solutions that address those requirements; keep the rationale and alternatives visible.
5. Involve relevant users throughout the work when practical, rather than only asking for approval after
  implementation.
6. Evaluate designs against the stated requirements using tasks and conditions representative of actual use.
7. Iterate from the evaluation evidence; a prototype’s completion is not the end of user-centred verification.
8. Consider the whole user experience and include the expertise needed for usability, accessibility and the domain.
9. Record which users or contexts were not represented and what decision those gaps leave unresolved.

## Preserve the boundary
- Preserve facts, quantities, terms, permissions, prohibitions, conditions, exceptions, warnings and required links.
- Do not invent a requirement, numerical threshold, clause number, user need or evidence to make a checklist look
  complete.
- A review or language edit does not authorise execution, deployment, source acquisition fees or user-data
  collection.
- These human-oriented principles can inform agent instructions, but do not prove how an agent will interpret them.

## Check and finish
- Check the result against the real task, including a relevant failure or recovery path; use intended-user evidence
  when available.
- Separate source-verified clause findings from Lean design suggestions and unchecked items.
- Return the artifact or scoped findings first, followed by material limits and the exact evidence still needed.
- Do not claim formal conformance from this short routine, a readability score or an unexecuted review plan.

## Worked distinction
The team likes a prototype but has not tested the recovery task with its intended users.
Treat team preference as design input, not user-validation evidence.
