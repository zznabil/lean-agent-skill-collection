# v8.17.0 — Lean Skill Composition

## Changes

- One primary lifecycle owner: explicit user designation, otherwise selected Get It Done, otherwise the unique substantive task skill after support roles are assigned. Unresolved competing claims stop affected actions.
- Quick Mode modifies authorized optional scope. Browser Automation owns execution evidence. Gauntlet Loop retains independent assurance. Project Context supplies readiness. Release retains its go/no-go gates. One owner reports final task status without hiding failed or missing assurance.
- Mandatory safety, repository policy, authorization and explicit acceptance precede role defaults. Quick Mode cannot weaken destructive safeguards, release gates or publication integrity.
- The affected execution, assurance, context, release and skill-design folders contain local composition fallbacks. Root activation is not assumed. No new canonical skill, role metadata, orchestration runtime or catalog-wide loading.
- Add focused OMP decision cases A–J and adversarial cases, calibrated source-loading and strict-Boolean checks, plus a replayable real-browser fixture with positive and broken-state controls.

- Preserve canonical script bytes under Windows Git line-ending conversion. The existing rejection suite now exercises real checkouts and a missing-LF-guard negative control.

## Compatibility

The 24 base skills, 27 integrated routines, six profile memberships and implicit/manual routing remain unchanged. Hermes PowerShell and batch installers remain in every generated profile and each standalone source pack. Remaining-standards and controlled-execution stay source-only and excluded from generated profiles. Source references, rights notices and the communication kernel remain intact.

## Verification and limits

See [composition contract](../../docs/SKILL-COMPOSITION.md) and the focused evaluator's report for exact host, model, source digests and case results. Static package checks prove inventories, integrity and preservation; they do not prove model obedience.
Live OMP decisions are limited to the frozen prompts and tested package. Browser UAT exercises a disposable rendered fixture through real browser actions, assertions, replay and reset. It does not establish arbitrary application acceptance or universal cross-host behavior. Untested agent hosts and production readiness are **NOT TESTED** / **NOT ASSESSED**. Standards-inspired wording is not formal conformance.

## Use and recovery

Select one primary skill and only the support needed for distinct responsibilities. Keep required failed verdicts visible. Stop dependent work on missing authorization, unavailable required support, ownership conflict or unsafe state. Repair within authorized scope and rerun affected verification.
Install using the existing profile or Hermes instructions. Existing skills need no migration or new configuration. To restore an earlier installation, use its retained package or installer policy backup; do not overwrite public tags or published assets.
