# v8.18.0 — Upstream Audit Hardening

## Changes

- Reconcile the 24-row base catalogue, current three-driver communication kernel and merged optional-pack status. Keep historical decisions dated and preserve unknown prior review pins in a machine-readable source ledger.
- Reuse the existing composition source checker for communication evaluation. Required reads must provide complete, matching source lines before the final answer; header-only, substituted, failed, unpaired and late reads cannot satisfy that evidence. Keep the prose rubric and no-skill/optional-skill modes.
- Treat invalid traces and host failures as unsuccessful evaluation runs rather than favourable negative-trigger evidence.
- Tighten the existing delegated-edit protocol: verify the intended base revision before editing, assign hidden/shared writes explicitly, and preserve unattributed changes.
- Add original decision and regression fixtures for late cancelled or obsolete results, workspace mismatches, independent defects, generated-copy coverage, public API preservation and evidence-guided actions.

## Compatibility

The 24 base skills, 27 integrated routines, six profile inventories and implicit/manual routing are unchanged. The remaining-standards and controlled-execution packs remain separate source packs. Existing Hermes installers, source rights and communication fallbacks remain supported. Installed profiles gain no new runtime dependency or global workflow. Source validation now also runs Python checks and requires Python 3.10+ available as `python` on PATH; existing CI already supplies it. No new third-party Python library is added.

## Verification and limits

The release packet records exact revisions, commands and outcomes. Required release checks include deterministic double builds, archive/inventory validation, rejection controls, pack checks, prose-preservation and the added offline calibration on PowerShell 7 and Windows PowerShell 5.1. Independent review checks the implementation against the accepted audit.

Synthetic controls exercise the checker and authored expected decisions. They do not establish live model obedience, runtime cancellation enforcement, cross-host equivalence, task-performance improvements or formal standards conformance. No fresh live OMP evaluation is claimed. Historical v8.17.0 live results remain evidence for that earlier tested revision only.

## Use and recovery

Use the existing profile or Hermes installation instructions. No new configuration or migration is required. If a required source read is absent or incomplete, repair the read and rerun the evaluation; do not bypass the evidence gate. Delegated edits stop at a mismatched base or unowned shared write until ownership is resolved.

Retain the prior v8.17.0 package and any installation backups for recovery. Restore through the existing installation process without overwriting unrelated user files. Existing public tags and release assets remain unchanged.
