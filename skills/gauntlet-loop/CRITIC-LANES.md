# Critic lanes

Select only lanes that can change the decision. Give each critic a charter and anti-charter. Use them to prevent duplicate work across parallel lanes. A finder does not grade its own finding.

Choose the uncertainty bias from asymmetric cost:

- Refute unsupported defect claims. Do not promote them.
- Keep suspected dead code, data, or compatibility behavior by default when false removal is costly.
- Default safety or release acceptance to fail or conditional when a false pass can harm users.

For causal investigations, first gather facts without a story. Then generate genuinely different hypotheses with checkable predictions. Assign one dedicated falsifier to each hypothesis. Derive confidence from surviving hypotheses and missing evidence, not a reviewer’s feeling.

- **Requirements:** check the real user goal, source-to-requirement traceability, task acceptance, standing Definition of Done, omitted behavior, bad assumptions, scope drift, compatibility, and measurable acceptance.
- **Visual:** use real screenshots and compare them with references. Check hierarchy, spacing, type, contrast, clipping, responsive states, focus, disabled, empty, error, scaling, localization expansion, and applicable WCAG 2.2 AA checks.
- **Interaction and real-user QA:** inspect the running artifact, not source claims. Test clean and stale state. Test launch, navigate, create, edit, save, reload, reopen, import/export, invalid input, keyboard use, resize, session expiry, interruption, persistence, and recovery. Check console, network, accessibility tree, saved output, and user-visible result. Cover every supported surface that the scope names.
- **Automated tests:** use unit, integration, end-to-end, regression, contract, property, fuzz, mutation, concurrency, migration, compatibility, load, performance, or security tests as applicable. Trace requirement → test condition → expected result → actual result → evidence. Distinguish `NOT TESTED`, `FAIL`, and `PASS`. A snapshot, “does not throw” assertion, or fully mocked test is insufficient if it still passes under representative broken behavior.
- **Model and procedure:** for simulators, migration plans, generated transformations, planners, or other internal models, verify replay against recorded and holdout evidence. Then execute the derived procedure on the real artifact. Test intermediate invariants and objective discovery. Transition accuracy alone does not establish acceptance.
- **Code correctness:** check behavior, control flow, errors, cleanup, types, data flow, dependencies, compatibility, observability, concurrency, and testability. Check the developer or operator contract: setup, commands, environment variables, ports, feature gates, and migrations.
- **Maintainability/simplification:** check canonical ownership, explicit boundaries, special-case growth, duplicated policy, hidden coupling, unnecessary wrappers, narration comments, placeholders, unjustified type escapes, defensive branches without a real failure model, dead code, and evidence-backed simplification. In a strict structural lane, search for a reframing that removes concepts, branches, modes, wrappers, or state. Recommend it only with evidence of contract preservation and migration cost. A refactor must reduce net complexity. It must not merely move complexity behind another layer. Use file size as an inspection signal, not a hard gate.
- **Security and privacy:** check trust boundaries, protected assets, abuse cases, authorization, secrets, injection, file safety, data purpose, minimization, access, retention and deletion, dependency ownership and provenance, lifecycle scripts, least privilege, and applicable ASVS controls. For AI or agent systems, use `AI-ASSURANCE.md`.
- **Reliability and operations:** check retries, idempotency, success/failure/unknown outcomes, races, data integrity, rollback, recovery, user-facing service objectives, structured logs, end-to-end correlation, bounded metric labels, tracing, symptom alerts, and cold startup.
- **Performance:** measure latency, throughput, memory, startup, network, or user-experience metrics under comparable conditions. Static review may report `potential impact`. Never fabricate values. Check variance and correctness. Check whether the change beats the baseline enough to justify its cost.
- **User information and cognitive accessibility:** apply IEC/IEEE 82079-1, ISO/IEC/IEEE 26514/26513, ISO/IEC 23859, ISO 21801-1, ISO 9241-171, ISO/IEC 29138, and ISO 704 only when relevant. Test intended user, task and context; findability; prerequisites; action; expected result; recovery; consequences; orientation after interruption; hidden memory; stable terms; layered detail; and actual user-task evidence. Easy-to-Read claims require intended-user co-review.
- **Document/data:** check claims, citations, calculations, reproducibility, consistency, caveats, methodology, chart accuracy, audience fit, and misleading certainty. Check both directions. Every claim must have support. Every material source fact must be represented or intentionally excluded.
- **Agent/skill/workflow:** test triggers and anti-triggers. Check conflicts, missing tools, malformed input, context rollover, prompt injection, tool permission boundaries, sensitive data, state poisoning, benchmark gaming, fabricated evidence, runaway loops, quota exhaustion, unsafe actions, dynamic code execution, automatic updates, resume determinism, failed-child handling, barrier justification, cap disclosure, and untrusted workflow source. When traces exist, evaluate the end outcome, full trajectory, and individual tool choices and arguments separately. Use a concrete AI risk or security baseline when scope warrants it.

For every finding, state lane, benchmark ID, severity, acceptance disposition (`blocking` or `nonblocking`), repair state (`open`, `fixed`, `blocked`, or `deferred`), confidence, exact evidence, reproduction, expected result, actual result, affected artifact, impact, and smallest repair direction. Use severity to describe impact. Use disposition to control acceptance. Do not use an ambiguous label such as `P2 blocked`.
