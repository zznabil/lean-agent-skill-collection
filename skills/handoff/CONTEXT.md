# Durable project context

Update only the requested scope. A useful context record points to the current source, real entry points, important contracts, decisions, verification and exact next action. Read task-relevant material rather than building a full repository map before every edit.

Mark observed facts, inference and unknowns with provenance and revision. Recheck date-sensitive state before reuse. Include enough coverage information to distinguish inspected areas from unexamined ones. Store links and concise decisions, not source dumps or conversation transcripts.

A reusable lesson belongs in one appropriate owner: a regression test, type/schema, project documentation or an explicitly approved memory entry. Do not automatically rewrite AGENTS.md, installed skills, hooks or global memory after a successful task. Those are trusted instructions and need scope-specific approval, an inspectable diff and a recovery path.

Redact secrets and unnecessary private details. Remove stale duplicate guidance rather than accumulating conflicting recipes. The next worker should be able to verify the checkpoint and continue without treating a historical pass as fresh evidence.
