# Review lanes

- **Requirements:** source-to-requirement traceability, task acceptance, standing Definition of Done, measurable checks, omitted behavior, scope drift, compatibility, unapproved reinterpretation, and the developer or operator contract: setup, commands, environment variables, default ports, feature gates, migrations, and version boundaries.
- **Code correctness:** functional behavior, error paths, cleanup, types, data flow, dependencies, compatibility, observability, concurrency, and testability. Trace side effects through relevant callers and interfaces. Read tests and specification before treating implementation as the contract.
- **Maintainability/simplification:** canonical ownership, explicit boundaries, special-case growth, duplicated policy, hidden coupling, unnecessary wrappers, dead code, and whether a smaller direct design preserves behavior. A refactor must reduce net complexity rather than relocate it. File size is a signal to inspect, not a defect by itself. Suspected dead behavior defaults to keep until dynamic, reflective, external, and configuration consumers are disproved.
- **Frontend:** real screenshots and interaction; applicable WCAG 2.2 AA checks, responsive layout, hierarchy, copy, loading, empty, error, focus, disabled, persistence, and realistic data.
- **Writing:** audience, structure, claims, citations, calculations, caveats, repetition, ambiguity, tone, unsupported certainty, and bidirectional source coverage.
- **Data/analysis:** source quality, joins, units, missing data, leakage, reproducibility, statistical method, charts, and conclusion fit.
- **Architecture:** constraints, boundaries, data ownership, trust boundaries, machine-checkable contracts, cross-surface policy parity, success/failure/unknown outcomes, migration, rollback, operations, and speculative complexity.
- **Agent operability:** cold startup from documented instructions, canonical non-interactive commands, environment and secret boundaries, a fast validation loop, deterministic outputs, agent-readable errors, and whether documentation matches actual behavior. Tool-environment limitations are not repository defects.
- **Security and supply chain:** protected assets, abuse cases, authorization, secrets, injection, file safety, least privilege, dependency ownership, maintenance, provenance, lockfile and transitive changes, lifecycle scripts, and concrete controls such as applicable ASVS requirements.
- **Reliability and operations:** retries, idempotency, races, data integrity, recovery, structured logs, correlation, bounded metrics, tracing, symptom alerts, runbooks, and rollback evidence.
- **Performance:** measured latency, throughput, memory, startup, network, or user-experience data under comparable conditions. Static findings are `potential impact`; inspect variance, correctness, and meaningful improvement before recommending complexity.
- **Agent/skill/workflow:** trigger precision, conflicts, unavailable tools, malformed input, prompt injection, tool permissions, sensitive data, state poisoning, context rollover, duplicate work, runaway loops, benchmark gaming, fabricated evidence, false completion, executable workflow trust, automatic updates, dynamic evaluation, resume determinism, child failure handling, barrier justification, structured boundaries, and silent caps. Use a concrete AI risk or security baseline when scope warrants it.
