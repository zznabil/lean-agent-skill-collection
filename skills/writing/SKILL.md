# Writing

Choose **draft** or **edit**. For substantial manuals, onboarding, embedded help, forms, UI text, warnings, errors, or recovery guidance, read [USER-INFORMATION.md](USER-INFORMATION.md). For agent policies, workflows, checklists, or consequential procedures, read [INSTRUCTION-EDITING.md](INSTRUCTION-EDITING.md).

## Communication kernel

1. **Language.** Use ASD-STE100-inspired sentence discipline. Prefer short active sentences, direct verbs and concrete wording. Keep technical meaning exact.
2. **Terminology.** Use ISO 704-inspired terminology discipline. Keep one preferred term for one concept within the artifact. Define specialised terms when ambiguity is plausible. Distinguish related concepts instead of using near-synonyms interchangeably.
3. **Mode.** Use Diátaxis when structure helps: how-to for actions, reference for facts or syntax, and explanation for mechanisms.

Do not activate other communication, requirements, safety, teaching, accessibility or engineering frameworks by default. Use a task-specific routine only when the task or user request requires it.

## Draft or edit

1. Identify the reader, task, desired result, evidence standard and requested voice.
2. Preserve facts, exact negation, conditions, exceptions, permissions, uncertainty, quotations and machine-sensitive text.
3. Remove throat-clearing, generic praise, request restatement, repetition, filler, decorative complexity and unsupported certainty.
4. Verify material facts, names, dates, calculations, quotations, citations, links and consequential wording.
5. Return the finished text. Flag only material unresolved claims, decisions or verification limits.

The communication kernel governs the surrounding reply. Do not insert Summary or TL;DR into the drafted artifact unless the user requests them.

## Agent-facing instructions

For skills, agent policies, prompts, workflows, checklists or handoffs, read [INSTRUCTION-EDITING.md](INSTRUCTION-EDITING.md). Treat the executing agent as the intended reader and the required action as the information need. Preserve the source's mandates, conditions, exceptions, links, resources and evidence.

Use the same terminology discipline for people and agents. Do not replace precise requirements with vague phrases such as "use judgement" or "follow best practices".

**User-facing:**

- Use short, active technical sentences (ASD-STE100-inspired).
- Keep terminology stable and concept-specific (ISO 704-inspired).
- Separate how-to, reference and explanation when useful (Diátaxis).
- Preserve genuine uncertainty, evidence limits, permissions, quotations, requested voice and artifact formats.
- Avoid surprise scope. Leave the result ready to use or resume.
