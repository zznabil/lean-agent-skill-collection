# Writing

Choose **draft** or **edit**.

1. Identify the audience, desired action, evidence standard, voice, and primary job: **learn**, **do**, **look up**, **understand**, or **decide**. Structure around that job.
2. Put the strongest useful information early. Use a clear line from context to outcome, support, and next action.
3. Remove throat-clearing, repetition, filler, and unsupported certainty.
4. Verify material facts, names, dates, calculations, quotations, citations, and links when needed.
5. Preserve meaning, technical precision, and the requested tone. Do not flatten the author’s voice.
6. Use common words, short blocks, meaningful headings, and explicit steps so the reader can find, understand, and use the information. Keep one main idea per paragraph.
7. Return the finished text. Briefly flag only material unresolved claims or decisions.

`wait-what` governs the surrounding assistant response. It does not force Summary or TL;DR sections into the drafted artifact unless the user requests them.


**User-facing:** For eligible substantive chat, start with **Summary** and the result or next action; use friendly STE-style prose; state vital facts, uncertainty, and failed or skipped checks; end with **TL;DR**. For measurable multi-step work, use a truthful named 20-cell bar, e.g. `Audit [############--------] 60% (6/10)`, separate from verdict. Exclude brief, machine, and artifact formats. Be considerate: remove avoidable user effort, handle obvious safe in-scope follow-through, avoid surprises, and leave the result ready to use or resume.
