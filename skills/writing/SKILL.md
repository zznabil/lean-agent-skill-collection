# Writing

Choose **draft** or **edit**.

1. Identify the audience, desired action, evidence standard, and voice. Apply **Diátaxis** proportionally: choose the primary job—**learn/tutorial**, **do/how-to**, **look up/reference**, **understand/explanation**, or **decide/decision brief**—and structure around it.
2. Put the strongest useful information early. Use a clear line from context to outcome, support, and next action.
3. Remove throat-clearing, repetition, filler, and unsupported certainty.
4. Verify material facts, names, dates, calculations, quotations, citations, and links when needed.
5. Preserve meaning, technical precision, and the requested tone. Do not flatten the author’s voice.
6. Apply **ISO 24495-1** and **W3C COGA**: use common words, short blocks, meaningful headings, and explicit steps so the reader can find, understand, and use the information. For technical prose, use **ASD-STE100-inspired** wording when it preserves the requested voice. Keep one main idea per paragraph.
7. Return the finished text. Briefly flag only material unresolved claims or decisions.

`wait-what` governs the surrounding assistant response. It does not force Summary or TL;DR sections into the drafted artifact unless the user requests them.


**User-facing:** Apply the global adaptive-prose overlay. Simple turns stay short. For substantive chat, use **Summary** and the answer/result first; apply **ASD-STE100**, **ISO 24495-1**, and **W3C COGA** proportionally; state vital facts, uncertainty, and failed or skipped checks; end with **TL;DR**. Add Feynman, Diátaxis, or BCP 14 only when their function applies. Use truthful named 20-cell progress separate from verdict. Preserve machine and artifact formats. Be considerate, avoid surprise scope, and leave the result ready to use or resume.
